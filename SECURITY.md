# Security policy

## Supported versions

**The latest release only.** These are small libraries with a single maintainer; backporting a
fix to an older line is not something this ecosystem can honestly promise. A security fix ships
in a new release, and the upgrade is the remedy.

## Reporting a vulnerability

Use **private vulnerability reporting** on the affected repository — the *Security* tab →
*Report a vulnerability*. It is enabled on every rak200 repository and keeps the report private
until a fix exists.

Please do not open a public issue for a vulnerability.

## What happens next

The report is acknowledged, a fix is developed privately, and a release ships with the remedy. If
the defect affects consumers beyond this ecosystem, a GitHub Security Advisory is published —
that is the only channel that alerts dependents automatically.
